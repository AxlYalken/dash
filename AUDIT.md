# Аудит кода — 15 сентября 2026

Проверена локальная версия Next.js-проекта для Netlify: API парсинга, генерации и чата, серверная конфигурация модели, схемы данных, работа с CSV/XLS/XLSX, ошибки и состояния React, импорты, зависимости и конфигурация публикации. Исправления внесены без добавления авторизации.

## Что проверено без обнаружения соответствующего опасного механизма

- В коде приложения нет `eval`, запуска shell-команд, `dangerouslySetInnerHTML`, загрузки URL, заданного пользователем, или записи загруженных файлов на диск.
- Текст отчёта и ответы модели отображаются как текст React; HTML из модели не исполняется.
- API-ключ читается на сервере; `NEXT_PUBLIC_*` для секретов не используется. В итоговый архив исключены `.env*`, кроме `.env.example`.
- API ограничивают реально прочитанные байты, а не только доверяют `Content-Length`. Проверяются схемы запросов, числа, роль последнего сообщения, формат файлов, пустые входы.
- Модель получает только данные отчёта и историю; инструментов выполнения кода, поиска или доступа к файловой системе нет. Промпты запрещают команды внутри отчёта, но это не математическая гарантия защиты от prompt injection.
- Потоки инсайта и чата тестируются до завершения генерации; проверяются пустые и некорректные ответы, ошибки провайдера и восстановление интерфейса.

## Проверки и границы результата

`npm test`: 76 тестов в 11 файлах прошли. `npm run build`: успешная production-сборка, включая TypeScript и ESLint.

`npm audit --audit-level=low`: 0 известных уязвимостей в текущем дереве зависимостей. Это результат базы npm, а не доказательство безопасности всего кода; внешняя поставка SheetJS также не получает гарантии только от npm audit.

Добавлены регрессионные тесты корректных сжатых/несжатых XLSX, повреждённых архивов, подделки размера распаковки, широких таблиц, предела текста, пустого заголовка, ограничения колонок и продолжения чата после отмены. Диагностические проверки исходных дефектов обновлены на проверку исправленного поведения. Тест намеренного падения компонента выводит `private details` только в локальном тестовом stderr: это искусственная проверка Error Boundary, не утечка данных приложения.

Это обзор кода и локальные проверки, не внешний пентест. Запросы с настоящим ключом, настройки аккаунта Netlify, CDN, журналы облака, мобильная клавиатура и фактическое качество ответов Ling не проверялись. Защита ZIP снижает риск распаковки, но не заменяет изоляцию парсера и не исключает неизвестные уязвимости SheetJS/формата XLS. Загрузки обрабатываются синхронно и при параллельных больших запросах могут нагружать процесс.

## Сохранённые ограничения личного проекта

- Авторизация намеренно отсутствует по требованию владельца. Если сайт опубликован, адрес API доступен извне; название «личный проект» не делает его закрытым. Внешние запросы могут расходовать лимиты модели. Авторизация и ограничение частоты запросов не добавлялись.
- Графики по-прежнему являются заглушками, история хранится только во вкладке.
- На Netlify ограничения загрузки могут сработать до приложения; для демо используйте файлы до 4 МБ. Парсер отклоняет нормализованные таблицы более 512 КБ вместо их скрытого обрезания.
- Автоопределение заголовков CSV неоднозначно; для полностью текстовых таблиц нужен явный `hasHeaders`, переключателя в UI пока нет.
- Модель может ошибаться в расчётах и поддаться инструкциям из отчёта. Не следует считать её выводы проверенными вычислениями.
