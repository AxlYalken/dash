# Narrative — AI-дашборд

## Что это за проект

Narrative принимает CSV, Excel или текст отчёта, формирует главный AI-инсайт и позволяет задавать вопросы по загруженным данным. Это прототип микро-SaaS с потоковыми ответами, тёмной темой и адаптивным интерфейсом.

## Стек технологий

- Next.js 15.5.25: App Router, серверные API routes, TypeScript, React 18.
- Tailwind CSS 3, shadcn/ui, neutral-тема, next-themes, Lucide.
- Framer Motion: появление секций, переходы состояний, потоковый текст.
- Vercel AI SDK 6, Vercel AI Gateway (модель задаётся через `AI_MODEL`), Zod.
- react-dropzone, Papa Parse для CSV, SheetJS 0.20.3 для XLS/XLSX.
- Vitest, React Testing Library, ESLint.

## Как запустить локально

Нужны Git, Node.js и npm. Зависимости приложения требуют Node.js 18.17 или выше; используйте поддерживаемую версию Node.js. В `netlify.toml` задан Node.js 22; локальная проверка выполнена на Node.js 26.0.0.

1. Клонируйте репозиторий. Замените `OWNER/REPO` на реальный адрес: у передаваемой локальной копии Git remote пока не настроен.

   ```bash
   git clone https://github.com/OWNER/REPO.git ai-narrative-dashboard
   cd ai-narrative-dashboard
   ```

   Если исходники уже есть локально, просто откройте папку с `package.json`.

2. Установите зависимости по lock-файлу:

   ```bash
   npm ci
   ```

   Для установки SheetJS нужен доступ к официальному `cdn.sheetjs.com`.

3. Создайте локальный файл окружения:

   ```bash
   cp .env.example .env.local
   ```

   В Windows PowerShell: `Copy-Item .env.example .env.local`.

   | Переменная | Назначение |
   | --- | --- |
   | `AI_GATEWAY_API_KEY` | Ключ Vercel AI Gateway; на Netlify обязателен API-ключ, OIDC не используется. |
   | `AI_MODEL` | Обязательно: полный идентификатор модели `провайдер/модель` из каталога Vercel. |
   | `SITE_URL` | Полный адрес сайта для OG-ссылок; локально `http://localhost:3000`. |

   Инсайт и чат работают через Vercel AI Gateway; отдельные ключи OpenAI и Anthropic не требуются. Ключ нельзя помещать в переменные с префиксом `NEXT_PUBLIC_`. `.env` и `.env.*` исключены из Git, `.env.example` — исключение без секретов. После изменения окружения перезапустите сервер.

4. Запустите разработку:

   ```bash
   npm run dev
   ```

   Откройте [localhost:3000](http://localhost:3000). Без ключа интерфейс и парсер работают, а AI-функции показывают понятную ошибку настройки.

### Проверки и production-сборка

```bash
npm test
npm run typecheck
npm run lint
npm run build
npm start
```

Тесты покрывают парсинг, потоковые API с тестовым провайдером, интерфейс чата, ошибки и восстановление компонентов. `npm run build` также проверяет типы и ESLint. Реальные ответы через AI Gateway без настроенного ключа не проверялись.

## Архитектура

1. **InputZone** принимает один CSV/XLS/XLSX или текст. После двухсекундной демонстрационной подготовки передаёт исходные данные в клиентский **DataInput**.
2. **`POST /api/parse-data`** нормализует файл в массив объектов или очищает текст. CSV обрабатывается Papa Parse, Excel — SheetJS. Ошибки возвращаются в JSON; пустые данные имеют код `EMPTY_DATA`.
3. **`POST /api/generate-insight`** получает нормализованный набор и передаёт его выбранной модели через Vercel AI Gateway. AI SDK стримит JSON `{ headline, subtext, suggestedQuestions }`; **HeroInsightWidget** показывает частичный ответ, не ожидая завершения.
4. **Ask the Data** использует `useChat` и **`POST /api/chat`**. Каждый запрос содержит весь отчёт и историю переписки. Отчёт помещается в системный контекст; промпт требует отвечать только по данным и признавать отсутствие информации. 3–4 вопроса-чипса генерируются вместе с инсайтом.
5. При новой загрузке история чата сбрасывается, активный ответ отменяется. Данные хранятся в памяти вкладки, сервер не сохраняет файлы на диск.

Основные файлы:

```text
app/page.tsx                 — главная страница
app/error.tsx                — резервный экран ошибки страницы
app/api/parse-data/          — парсинг и нормализация
app/api/generate-insight/    — потоковый инсайт и вопросы
app/api/chat/                — потоковый чат по отчёту
components/dashboard/       — интерфейс и управление загрузкой
components/error-boundary.tsx — изоляция ошибок отдельных блоков
components/ui/              — базовые компоненты shadcn/ui
lib/                        — типы, Zod-схемы, промпты и обработка ошибок
```

Повторная генерация использует уже распарсенные данные. Ошибки отображаются в зоне загрузки, Hero и графиках; отдельные Error Boundary защищают блоки от взаимного влияния. Общие радиусы и тени находятся в `app/globals.css` и `tailwind.config.ts`.

## Известные ограничения

- **Графики — заглушки.** Реализованы карточки и состояния загрузки данных/ошибок, но построение графиков не входило в выполненные этапы.
- **Подготовка InputZone занимает искусственные 2 секунды.** Это демонстрация этапов; реальный парсинг и запрос модели выполняются после неё.
- **Нет БД, аккаунтов и сохранения истории.** После перезагрузки нужно загрузить отчёт заново. Нет авторизации и собственного ограничения частоты запросов: перед открытым доступом нужны защита API и контроль расходов.
- **Нет RAG и обработки больших отчётов.** Парсер принимает до 10 МБ, 50 000 строк, 500 колонок и 1 000 000 ячеек. Инсайт — до 512 КБ JSON и 100 000 символов текста; чат — до 768 КБ JSON, 40 сообщений и 2000 символов вопроса. При превышении лимита возвращается ошибка, данные не обрезаются молча. Ограничения тела запроса у хостинга могут быть строже.
- **Excel:** первый непустой лист, стандартные XLS/XLSX; защищённые книги и HTML/XML под расширением XLS не поддерживаются. Формулы не вычисляются, используются сохранённые значения. **CSV:** UTF-8; ведущие нули и большие числа сохраняются строками, пропуски — `null`.
- **Заголовки определяются эвристически.** В таблице только из строк первая строка по умолчанию сохраняется как данные. API парсера поддерживает `hasHeaders=true/false/auto`; отдельного переключателя в UI нет.
- **LLM может ошибаться.** Промпты запрещают выдумки, структура ответа проверяется, но это не гарантирует фактическую достоверность. Данные отправляются выбранной модели через Vercel AI Gateway; ключ хранится только на сервере. Таймаут генерации — 55 секунд. `maxDuration = 60` не настраивает лимит Netlify: платформа ограничивает выполнение потоковой функции 60 секундами.
- **Зависимости обновлены по аудиту безопасности:** Next.js 15.5.25, согласованный eslint-config-next, Vitest 4.1.11 и PostCSS 8.5.28. Override для PostCSS внутри Next.js заменяет уязвимую закреплённую версию; при следующих обновлениях Next.js перепроверьте необходимость override. Повторяйте `npm audit` перед публикацией: база известных уязвимостей меняется.
- Мобильная вёрстка проверена на ширинах 320 и 375 px. Поведение физической экранной клавиатуры требует проверки на устройстве.

## Деплой на Netlify

Next.js 15.5.25 работает через OpenNext-адаптер `@netlify/plugin-nextjs` 5.15.13. Зависимость и lock-файл добавлены в проект. В `netlify.toml` указаны команда `next build`, каталог `.next` и плагин; Node.js для сборки — 22. Файл должен находиться рядом с `package.json`.

### Переменные окружения

Добавьте в Netlify → Project configuration → Environment variables:

- `AI_GATEWAY_API_KEY`
- `AI_MODEL`
- `SITE_URL`

Ключ и модель должны быть доступны в области **Functions**, адрес сайта — в **Builds** (метаданные формируются при сборке). Можно выбрать все области. Настройте значения для Production и нужных Deploy Previews. После изменения переменных запустите новый деплой. Не записывайте секреты в `netlify.toml`, Git или `NEXT_PUBLIC_*`.

Для выбранной модели задайте `AI_MODEL=inclusionai/ling-3.0-flash-fin`, а `SITE_URL` — полный адрес сайта Netlify или своего домена. `.env.example` — шаблон для локальной разработки, он не задаёт переменные в облаке. Дополнительные переменные Vercel, ключ OpenAI и токен Netlify для работы приложения не нужны.

Хостинг перенесён на Netlify, но сервис моделей остаётся Vercel AI Gateway: это внешний API, доступный по обычному серверному API-ключу. Поддержка OIDC удалена из проверки конфигурации. Тариф модели проверяйте в [каталоге Gateway](https://vercel.com/ai-gateway/models/ling-3.0-flash-fin).

### Через GitHub и интерфейс Netlify

1. Загрузите проект в GitHub с сохранением структуры папок. Не загружайте `node_modules`, `.next`, `.netlify` и `.env.local`. Обязательно добавьте `netlify.toml`, `package.json`, `package-lock.json`, `app`, `components` и `lib`.
2. В Netlify выберите **Add new project → Import an existing project → GitHub** и репозиторий.
3. Если проект находится в подпапке, укажите её как Base directory. Проверьте Build command: `next build`, Publish directory: `.next`. Настройки читаются из `netlify.toml`.
4. Добавьте переменные окружения, описанные выше, и запустите Deploy. Если адрес сайта появился после первой сборки, обновите `SITE_URL` и повторите деплой.
5. Последующие коммиты в подключённую ветку запускают автоматический деплой.

### Через Netlify CLI

Из папки с `package.json`:

```bash
npm ci
npx netlify-cli@latest login
npx netlify-cli@latest init
```

`init` подключает Git-репозиторий для автоматических деплоев. Для уже созданного сайта используйте `npx netlify-cli@latest link`; для нового сайта без Git — `npx netlify-cli@latest sites:create`, затем при необходимости `link`.

Задайте переменные в интерфейсе Netlify, затем создайте проверочный деплой:

```bash
npx netlify-cli@latest deploy --context production
```

Текущая CLI по умолчанию выполняет сборку вместе с адаптером и загружает файлы и функции. После проверки опубликуйте:

```bash
npx netlify-cli@latest deploy --prod
```

Не используйте статическую загрузку `.next` через drag-and-drop или `--no-build` после одного `next build`: серверным API нужны функции, созданные адаптером. [Документация CLI](https://cli.netlify.com/commands/deploy/).

### API и потоковые ответы

Все три API route используют `runtime = "nodejs"`; Edge Runtime и middleware отсутствуют. Импортов `@vercel/kv`, `@vercel/blob`, `@vercel/analytics` нет, дополнительных хранилищ переносить не нужно. `next/og` остаётся частью Next.js.

Netlify поддерживает Route Handlers и Response Streaming через адаптер. Инсайт возвращает `ReadableStream`, чат — поток SSE AI SDK; `useChat` обращается по относительному `/api/chat`. Переписывать протокол не требуется. Заголовки `Cache-Control: no-store, no-transform` сохранены. Тесты проверяют выдачу первых фрагментов до завершения модели. [Поддержка Next.js](https://docs.netlify.com/build/frameworks/framework-setup-guides/nextjs/overview/).

На Netlify лимит потоковой функции — 60 секунд; внутренний таймаут приложения — 55 секунд. Лимит тела запроса платформы — 6 МБ, а для бинарных данных из-за кодирования эффективный предел около 4,5 МБ. Он может сработать до обработчика с его лимитом 10 МБ: для демо используйте файлы до 4 МБ. [Лимиты Functions](https://docs.netlify.com/build/functions/configuration/).

После деплоя загрузите небольшой CSV, дождитесь инсайта и задайте вопрос в чате. Проверьте постепенное появление ответа, остановку генерации и сообщение при ошибке. Локальная сборка и тесты не подтверждают реальный запрос с ключом или работу потока через CDN Netlify; это проверяется на опубликованном сайте. Деплой в рамках подготовки не выполнялся.
